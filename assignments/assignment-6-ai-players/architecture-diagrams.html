Key Pattern: Strategy Pattern + Builder Pattern. The Character class delegates combat behavior to interchangeable strategies, demonstrating the Open-Closed Principle. CharacterStats uses the Value Object pattern (Java record) for immutability.

3. Strategy Pattern - Combat Behaviors

Pattern: Strategy Pattern. Different attack and defense algorithms are encapsulated in separate classes, allowing characters to have varied combat behaviors without inheritance. Strategies can be swapped at runtime.

4. Player Hierarchy - Decision Making

Key Pattern: Strategy Pattern + Adapter Pattern. Different Player implementations provide different decision-making algorithms. LLMPlayer acts as an adapter, converting LLM text responses into GameCommand objects.

5. Command Pattern - Action Execution

Pattern: Command Pattern. Game actions are encapsulated as objects, enabling undo functionality, command history, and separation of action execution from action invocation. This makes the system extensible to new action types.

6. Game Flow Sequence

Flow: Main game loop managed by GameController (Facade + Mediator patterns). The controller orchestrates turn-based gameplay, coordinating between players, characters, and command execution while maintaining game state.
